## 二、面试高频问题 & 参考回答

**Q1：为什么清洗时剔除缺失 Customer ID 的数据？剔除 22% 会不会影响结论？**
> 因为项目核心是用户经营分析（RFM、留存），没有 Customer ID 的行无法归因到人，保留反而会污染客户层指标。我做过口径对比：这些散单对月度营收走势的影响是整体抬升约 20% 但不改变趋势形态，所以在「趋势类」结论上口径影响可控。这个 trade-off 我在报告里明确写了。

**Q2：复购率 72% 和次月留存 20% 矛盾吗？**
> 不矛盾，这是统计口径的差异。72% 是 25 个月观察窗内的「曾复购」比例，而次月留存是队列口径下「下个月就回来」的比例。两者差异恰好说明客户是「间隔性回流」——平均复购间隔 51.7 天，他们没有流失，只是低频。所以我的建议不是拉新，而是在第 35-40 天做召回。

**Q3：RFM 的分位数打分为什么要用 rank(method='first')？**
> 因为 F（频次）和 M（金额）有大量重复值，直接 qcut 会出现分箱边界重复的报错。先 rank 再分箱等价于按排名分五等份，结果稳定可复现。

**Q4：你的异常值是怎么处理的？为什么不删？**
> 用 3×IQR 只抓极端大额订单，且只打标不删除。因为大额订单是真实业务（B2B 批发客户），删掉会系统性低估营收。我做了敏感性分析：全量营收 £17.7M，剔除极端值后 £10.0M——这个巨大差异本身就是「客户集中」的证据，和 RFM 分析结论互相印证。

**Q5：pandas 和 SQL 双引擎验证，具体怎么做的？**
> 同一套指标（月度营收、复购率、TOP 客户、国家占比）分别用 pandas 和 SQLite 各算一遍，8 条 SQL 里用了 NTILE 窗口函数算客户百分位、LAG 算复购间隔。两边结果一致，也证明了同一分析我可以用两种工具实现。

**Q6：如果让你接着做，你会做什么？**
> 三件事：① CLV 建模（BG/NBD + Gamma-Gamma）替代静态 RFM，预测客户未来价值；② 用 Prophet/LightGBM 做月度销量预测支撑旺季备货；③ 搭 Streamlit 看板让业务方能自助查看。

**Q7：这个项目最有挑战的地方？**
> 两处：一是清洗口径的决策——22% 缺失客户 ID 的数据处理方式直接影响所有结论，我通过对比口径确认了影响范围；二是把「复购率高」和「留存差」这对表面矛盾的指标解释清楚，队列分析让我看到了整体指标看不到的结构性问题。

## 三、上传 GitHub 的操作步骤（在你自己电脑上）

1. 在 GitHub 网页上新建一个仓库：名字 `ecommerce-analysis`，**Public**，不要勾选「Add README」（本地已有）
2. 在项目文件夹打开终端：

```bash
cd ecommerce-analysis
git init
git add .
git commit -m "feat: 电商交易数据分析项目（清洗+SQL+RFM+留存+可视化）"
git branch -M main
git remote add origin https://github.com/你的用户名/ecommerce-analysis.git
git push -u origin main
```

3. 刷新仓库页面，确认 README 的图表能正常显示（GitHub 会自动渲染 markdown 里的相对路径图片）

- commit 拆成多个（先清洗、再分析、再文档），显示规范的工作流
